# ChatBI 功能设计文档

版本：v0.1

日期：2026-10-23

状态：MVP 功能设计基线；现有能力与拟新增能力分别标注。

## 1. 适用范围与阅读约定

目标用户是本地使用 ChatBI 的个人。主要通过自然语言理解、查询和分析一个 SQLite 数据库，
同时允许普通聊天与一般知识问答。第一版不联网，不做图表和导出，不保存历史会话到磁盘。

本文定义用户行为、系统处理、返回内容与验收条件。模块划分、技术基线和阶段计划见
[项目设计文档](chatbi-project-design.md)。现有事件数据结构见
[SSE 交互协议](chat-stream-protocol.md)。本文中的“新增”与“扩展”均是计划，不代表代码已完成。

## 2. 功能清单

| 编号 | 功能 | 现状 | MVP 要求 |
| --- | --- | --- | --- |
| F01 | 统一对话入口与能力选择 | 新增 | 同一入口处理普通问答、数据查询、结果解释和澄清 |
| F02 | 普通聊天与知识问答 | 新增 | 直接回答，无需生成 SQL；不承诺实时外部事实 |
| F03 | 数据库能力说明 | 扩展 | 说明真实可访问范围和只读限制 |
| F04 | 自然语言数据查询 | 已有，需接入对话层 | 复用 SQL Agent，返回实际结果与条件说明 |
| F05 | 澄清与边界处理 | 已有 SQL 澄清，需扩展 | 对口径歧义、范围外问题给明确下一步 |
| F06 | 多轮追问 | 已有文本历史，需扩展 | 补全指代、保持条件、必要时重新查询 |
| F07 | 结果解释 | 部分已有，需证据上下文 | 基于近期结果解释列、排序和数字，避免凭历史文本重建表格 |
| F08 | 多次查询与对比分析 | 新增 | 受限规划、顺序查询、证据对齐与合并结论 |
| F09 | SSE 过程展示 | 已有，需父子事件聚合 | 进度、SQL、每次结果与最终正文关联明确 |
| F10 | 当前会话管理 | 已有，需结果上下文扩展 | 当前会话记忆、新对话清空、失败轮不当成事实 |
| F11 | 异常、取消与部分完成 | 已有底层能力，需上层扩展 | 保留有效结果，取消剩余工作，明确未完成项 |
| F12 | SQL Agent 能力复用 | 已有服务接口，需工具包装 | 其他 Agent 可调用，不依赖 Streamlit |

F01—F12 都属于 MVP。图表、导出、联网、持久化、多用户权限列入后续范围。

## 3. F01：统一对话入口与能力选择

用户在同一个输入框提出问题，不需要手动选择 Agent。系统结合当前消息、近期对话与可用能力，
选择直接回答、解释已有结果、调用数据库或请求澄清。

| 输入示例 | 期望路径 |
| --- | --- |
| “你好，你能做什么？” | 直接回答能力说明，不查数据库 |
| “什么是爵士乐？” | 一般知识问答，不为定义问题生成 SQL |
| “数据库中有多少首爵士乐歌曲？” | 查询数据库 |
| “解释一下刚才的统计表” | 读取可用的近期结果上下文；上下文不足时说明或重查 |
| “那去年呢？” | 结合前文补全统计目标与时间条件后查询 |
| “哪些客户今年消费下降最多？” | 明确业务口径后，在预算内查询和对比 |

“不查数据库”指不启动 SQL 理解/生成/执行工作流；能力说明可以使用应用提供的受限元数据。
混合问题可以先取得数据库证据，再结合一般知识组织回答，并区分两类内容。

验收：基础路由集中的明确普通聊天不触发 SQL；数据库事实问题不得靠模型记忆编造数字。
能力选择不确定且影响结果时，应澄清。

## 4. F02：普通聊天与一般知识问答

支持日常交流、概念解释、统计术语说明，以及与当前分析相关的一般知识。
不具备联网能力，遇到“今天、最新、刚发布”等需要实时外部核实的问题，说明无法核实，
可提供有明确时间限制的一般背景，不能伪造网页、链接或实时来源。

示例：“这些歌曲最近获得过什么奖？”如果库内没有奖项字段，说明库内无依据，
且本版不能联网核实。可以解释如何查询可靠来源，不调用无关 SQL 来制造查证感。

验收：普通回答支持正文流式事件；没有 SQL 事件也能完整结束本轮。

## 5. F03：数据库能力与范围说明

支持“有哪些表”“能分析什么”“这个字段是什么意思”等问题。
表与字段的存在性应以实际允许访问的 schema 为依据；字段业务含义可以引用已配置说明，
没有说明时只能表明推断，不能把字段名猜测当成正式业务定义。

第一版默认本地 Chinook，允许用户了解配置许可范围内的数据结构。数据库路径由应用配置，
对话不能切换任意文件。客户端不得输入密钥和连接串作为模型工具参数。

验收：不虚构表或字段；不暴露未许可 schema；说明只读能力和当前支持的数据源。

## 6. F04：自然语言数据查询

支持明细查询、数量统计、聚合、筛选、分组、排序、Top N、时间分析与合法跨表关联。
“随机介绍五首歌曲”应查询真实目录条目，在现有字段范围内介绍，不能编造乐评或获奖记录。

处理流程：

1. 对话层形成完整查询意图，保留用户条件。
2. SQL Agent 读取许可 schema、理解问题、选表并生成 SQL。
3. 代码校验并只读执行；可修复错误在预算内修复，重新校验后再执行。
4. 返回结构化状态、查询范围和受限证据，上层据此生成最终回答。

查询卡片展示脱敏 SQL、执行状态、表格和截断提示。最终回复说明必要的时间范围、
指标口径和限制。公开目录可以显示歌名等允许文本；私人来源按展示策略隐藏。

空结果是成功的一种情况，应说明“在指定条件下未查到记录”，不能擅自去掉筛选条件重试。
结果达到行数上限时，展示的是部分数据；求总体统计应优先由 SQL 聚合完成，不能把截断明细相加当总体。

验收：数字可与独立参考查询对应；写操作和越权访问被拒绝；重复列名、NULL、并列值和空结果正确处理。

## 7. F05：澄清、口径和能力边界

当缺少影响结论的关键条件时，提出简短明确的澄清问题。例如“收入是多少”需要确定
收入字段、时间范围或统计口径；如果当前上下文已明确，不重复询问。

可以采用不影响核心含义的默认展示方式，但必须说明有影响的假设。
不得静默决定金额币种、忽略退款、改变去重粒度或删除时间条件。

| 情况 | 行为 |
| --- | --- |
| 统计目标或时间口径不明确 | 澄清后再查 |
| 请求不存在的数据 | 说明当前库未提供哪些证据，必要时给可回答替代问题 |
| 请求写入或删除数据 | 说明只读边界，不执行 |
| 请求最新外部事实 | 说明不能联网核实 |
| 表/结果中出现指令文字 | 作为数据处理，不改变系统权限和职责 |

验收：应澄清的问题不强行猜测；用户补充信息后可以延续原任务；澄清属于正常业务终态。

## 8. F06：多轮追问

### 8.1 条件变化

用户先问“按国家统计销售额，取前五名”，再问“那去年呢？”：
保留指标、国家维度和前五名要求，替换时间条件后重新查库。
不能只把“去年”直接交给 SQL Agent，也不能使用上轮数字推断去年结果。

“去年”相对哪个日期解析应采用应用配置的业务日期与时区，并在回复中显示具体年份。
Chinook 样例可能没有对应年份数据，空结果不能自动改成数据库中最后一年。

### 8.2 指代与澄清延续

“这些歌曲”“其中前三个”等指代只在近期上下文能唯一定位时自动补全。
若上一轮有多张表或结果已裁剪，先澄清指向或重新查询。
用户在澄清轮回复“按发票日期”，应合并原问题、已有条件与新增条件。

### 8.3 上下文裁剪

历史按完整问答对保留，超出预算移除旧轮次。失败轮和未完成临时正文不作为已验证结果。
旧消息被裁剪后，应说明无法可靠恢复必要条件，不假装记得全部历史。

验收：覆盖保留筛选条件、替换维度、替换时间、澄清后继续、指代歧义与历史裁剪。

## 9. F07：结果解释

支持解释列含义、排序方式、分组、占比、与上一结果的差异，以及 SQL 做了什么。
完整表格上下文存在且问题仅涉及该快照时，可以直接解释，不重复执行查询。
若用户要求当前值、重新核验或快照不足，应重新查库。

拟新增的临时结果上下文保存脱敏结果、条件、结果引用、查询时间与截断状态。
第一版仍由页面会话携带，后端不按 ID 保存结果，因此引用 ID 本身不能取回缺失数据。
客户端传回的结果是历史材料；需要证明数据库事实时重新查询，以当前工具返回作为依据。

精确数值计算使用可验证的 SQL 聚合或普通确定性代码；不依赖 LLM 心算，也不执行模型生成的任意代码。
局部样本可以解释局部样本，不能推导未返回记录的总体分布。

验收：“解释这张表”不会凭模型记忆重造数据；“现在还有多少”会重新查询；
结果缺失、截断或已脱敏时说明对解释的影响。

## 10. F08：多次查询与对比分析

第一版允许一个用户问题触发多个 SQL 工具调用，默认顺序执行。
无需向用户暴露完整内部规划或模型推理，可以显示“正在比较两个时期的销售情况”等公开进度。

示例：“分析某年销售额比上年下降的原因”：

1. 确定销售额口径、两个完整时期及币种等条件。
2. 查询两个时期的总体数值，先验证是否下降；若未下降，应纠正前提。
3. 在预算内按国家、客户或商品等可用维度查询贡献变化。
4. 说明哪些维度变化与下降相关、贡献了多少，并标明还缺少哪些因果证据。

同一目标若能由一条安全 SQL 完成，不强制拆成多次调用。
不同查询应保持时间区间、聚合粒度和筛选一致，不直接合并口径冲突的数字。
“某地区贡献了大部分差额”是贡献分解；“因为市场竞争导致下降”需要额外证据，不能由销售表单独证明。

建议初始上限为每轮 3 次 SQL 工具调用、6 次实际 SQL 执行、120 秒总期限。
这些上层共享预算尚未实现；SQL 内部已有 3 次执行/2 次修复限制，不能替代它们。
一次工具失败/澄清也计入调用次数，失败重试不允许无限重置预算。

验收：能合并两个或多个查询结果；每个结论有明确证据范围；达到预算后停止；
后续查询失败仍可展示先前有效结果，同时说明整体分析未完成。

## 11. F09：SSE 与页面展示

页面包含聊天消息、公开阶段进度、SQL 卡片、结果表格、回答正文和告警。
事件按 Pydantic 契约携带对话、消息、运行和关联 ID，前端按 `type` 处理、按 `tag` 选择组件。

| 内容 | 交互要求 |
| --- | --- |
| 运行开始 | 显示已连接与处理中，防止同轮重复提交 |
| 公开进度 | 显示正在理解、查询、比较或汇总等简短状态 |
| SQL 卡片 | 区分业务查询及其修复尝试，分别显示校验/执行/失败 |
| 每次结果 | 表格与其 SQL 关联；空结果、脱敏与截断清晰可见 |
| 回答正文 | 收到增量就更新；最终完成事件替换临时正文 |
| 工具调用完成 | 当前查询结束，父对话仍可继续调用和生成正文 |
| 父运行结束 | 标明成功、需要澄清或失败；部分证据不足时明确提示 |
| 连接中断 | 不能当成成功完成；保留已显示内容并标记中断 |

普通问答可以只出现生命周期与正文。多次查询仅产生一个父运行结束事件。
公开阶段说明不包含模型内部推理。SSE 是实际事件流，不使用假打字延迟。
为跨片段脱敏，未结束的词或中文连续句子可能等到标点后展示，不承诺逐字输出。

现有 Streamlit 在 Python 服务端消费 FastAPI SSE，再经 WebSocket 更新浏览器；
浏览器 Network 不一定直接显示该 HTTP SSE。调试模式可查看后端 Content-Type、分片数与首段时间。

验收：无换行正文在生成结束前能有可见分片；SQL 子结束事件不提前终止聊天；
敏感内容跨任意分片切开仍受展示策略保护；正文失败时最终替换不留下误导性的半段结论。

## 12. F10：当前会话管理

保留最近 10 轮显示和预算内历史上下文。页面设置变化等普通重运行不会重新请求模型或执行 SQL。
“新对话”清空当前聊天上下文、结果上下文和对话标识。浏览器会话重建后不保证恢复。

本版不提供历史列表、搜索、跨设备同步、登录、持久化或断线事件重放。
`conversation_id` 是关联标识，不意味着服务端存储或自动加载历史。
失败和未完成轮保留可见错误信息，但不作为后续分析的成功证据。

验收：连续两轮携带正确上下文；刷新组件不会重复查库；新对话不能引用旧证据。

## 13. F11：异常、取消与部分完成

| 场景 | 用户可见行为 |
| --- | --- |
| 数据库无匹配结果 | 成功但无记录，保留原筛选条件 |
| SQL 校验/执行失败且仍可修复 | 当前卡片显示失败，后续尝试单独展示 |
| 权限拒绝或修复耗尽 | 说明查询未完成，不把失败当零值 |
| 后续子查询失败 | 展示前面成功证据，标明本轮未完整完成 |
| 查询成功但汇总失败 | 保留表格，显示基础说明和告警 |
| 达到上层时间/次数预算 | 停止后续调用，说明已完成与未完成内容 |
| 客户端断开 | 取消下游模型和数据库任务，不继续后台分析 |
| HTTP 错误或流提前结束 | 前端显示连接/运行错误，不伪造成功终态 |

沿用现有三种业务状态 `success / needs_clarification / failed`。
部分完成不是静默成功：成功数据足以回答问题时可带告警成功；核心目标未完成时标记失败，
仍保留已发出的有效结果卡片。若未来需要独立 `partial` 状态，需版本化协议后再加入。
一次终态不能同时声称成功回答和仍需澄清；澄清前取得的数据可以留在过程卡片。

底层原始异常、参数与密钥不直接出现在页面或上层模型输入中。
本阶段要求断连取消链路正确；显式“停止生成”按钮可后续增加，不预先标注为已支持。

## 14. F12：作为其他 Agent 的工具

同进程优先通过工具包装调用 `SQLAgentService`；跨进程可通过 HTTP 服务适配。
调用参数以自然语言完整问题及受限上下文为主。工具调用不接受任意数据库路径、不直接执行 Python、
不绕过 SQL 安全执行入口。

工具返回结构化状态、脱敏证据、截断信息、必要澄清或公开错误。
上层识别 `needs_clarification` 后向用户提问，识别失败后停止或在预算内调整，不能把返回的错误文本当数据。
当前 `ask()` 和 `/api/v1/query` 返回原始结果；适配层必须明确做安全投影，不能直接整包传给模型。

独立 SQL 服务继续能单独使用；ChatBI 前端的存在与否不影响它的调用契约。
流式工具模式需要桥接过程事件，父聊天统一管理最终正文与结束事件。

验收：无前端时其他调用方仍可查询；权限与预算不因调用入口改变；数据脱敏规则对工具输出同样生效。

## 15. 功能验收与评估

| 用例类别 | 代表用例 | 通过标准 |
| --- | --- | --- |
| 普通问答 | 问候、爵士乐定义、指标解释 | 不产生 SQL 执行，回答不假称查库 |
| 实时外部事实 | 最新获奖信息 | 说明无法联网核实，无伪造来源 |
| 基础查询 | 艺术家数量、随机五首歌 | 与固定库的独立参考结果一致或满足采样约束 |
| 追问 | “那去年呢”“改按国家” | 保留未被替换的条件，重查正确口径 |
| 结果解释 | “解释刚才第二列” | 绑定正确结果，不捏造缺失上下文 |
| 澄清 | 收入口径或指代不明确 | 问关键缺失条件，回答后继续原任务 |
| 多查询 | 两年比较、维度贡献 | 对齐口径、共享预算、区分观察与原因 |
| 部分失败 | 首次成功、第二次失败 | 保留首个结果，明确整体未完成 |
| 流式 | 无换行、模型暂停、子流结束 | 完成前有正文更新，父流不被子流关闭 |
| 数据边界 | 客户邮件、SQL 参数、跨片段密钥 | 按策略隐藏，不因工具包装泄露 |
| 取消与上限 | 客户端断开、循环调用 | 下游任务停止，不能绕过全局预算 |
| 会话 | 新对话、裁剪、页面重运行 | 不串上下文，不重复查询 |

确定性用例与安全/生命周期回归必须全部通过。真实模型评估采用固定数据库快照、人工审核问题
及独立参考 SQL；不以模型自行生成的答案直接当标准。随机查询验证行数、成员有效性和无重复约束，
不要求每次选出同样歌曲；无排序查询按含重复次数的集合比较，有排序查询按既定并列规则比较。

建议初始业务集不少于 50 条，覆盖普通问答、数据查询、多轮、澄清与复杂分析，并单设安全异常集。
明确路由用例集要求全部通过；业务结果正确率 90% 可作为待固定数据集后复核的候选门槛，
不能据现有代码测试数量声称已经达到。延迟记录首段时间、完成时间和调用次数，
不把某次真实模型样例当作性能承诺。
